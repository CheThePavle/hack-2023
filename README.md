# Сайт для управления мероприятиями

## 1. Общая информация

Проект представляет собой сайт для публикации и управления мероприятиями. Пользователи могут просматривать мероприятия, регистрироваться, приобретать билеты и задавать вопросы организаторам.

**Технологии:** Laravel 9, PHP, MySQL, HTML, CSS, JavaScript.

## 2. Структура базы данных

База данных содержит следующие основные таблицы:

| Таблица | Описание |
|---|---|
| `user` | Пользователи системы, контактные данные и пароли |
| `role` | Роли пользователей: оператор, администратор, организатор, пользователь |
| `permission` | Список доступных разрешений |
| `user_permission` | Связь пользователей с дополнительными разрешениями |
| `event` | Информация о мероприятиях |
| `category` | Категории мероприятий |
| `status` | Статусы мероприятий: отправлено, отклонено, опубликовано |
| `type_ticket` | Типы билетов, их стоимость и количество |
| `ticket` | Приобретённые билеты пользователей |
| `question` | Вопросы пользователей и ответы организаторов |

### Основные связи таблиц

- `user` → `role` — каждый пользователь имеет одну роль.
- `user` → `event` — пользователь может создавать мероприятия.
- `category` → `event` — каждое мероприятие относится к категории.
- `status` → `event` — каждому мероприятию присваивается статус.
- `event` → `type_ticket` — мероприятие может иметь несколько типов билетов.
- `type_ticket` → `ticket` — каждый билет относится к определённому типу.
- `user` → `ticket` — пользователь может приобретать билеты.
- `user` → `question` — пользователь может задавать вопросы.
- `event` → `question` — вопросы относятся к конкретным мероприятиям.
- `user` → `user_permission` → `permission` — дополнительные разрешения пользователей.

## 3. Маршрутизация (Routes)

Все маршруты определены в `routes/web.php`. Для обработки запросов используются контроллеры Laravel.

### 3.1. Публичные страницы

Доступны всем посетителям сайта.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/` | Главная страница со списком мероприятий |
| GET | `/notfound` | Страница 404 |
| GET | `/forbidden` | Страница 403 |
| GET | `/event/{id}` | Просмотр мероприятия |
| GET | `/login` | Страница авторизации |
| GET | `/register` | Страница регистрации |

### 3.2. Регистрация и авторизация

| Метод | URL | Назначение |
|---|---|---|
| POST | `/user/create` | Регистрация пользователя |
| POST | `/user/auth` | Авторизация пользователя |
| GET | `/user/logout` | Выход из аккаунта |

### 3.3. Личный кабинет

Доступ ограничен middleware `checkAuth` — только для авторизованных пользователей.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/lk` | Главная страница личного кабинета |
| GET | `/lk/organizer` | Кабинет организатора |
| GET | `/event/{id}/end` | Завершение мероприятия |
| DELETE | `/event/{id}` | Удаление мероприятия |

### 3.4. Функции организатора

Доступ ограничен middleware `checkOrganizer`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/eventform` | Форма создания мероприятия |
| POST | `/event` | Создание мероприятия |
| PATCH | `/question/{id}/reply` | Ответ на вопрос пользователя |

### 3.5. Панель администратора

Доступ ограничен middleware `checkAdmin`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/admin` | Главная страница администратора |
| GET | `/admin/category` | Управление категориями |
| POST | `/admin/category` | Добавление категории |
| DELETE | `/admin/category/{id}` | Удаление категории |
| GET | `/admin/category/list` | Получение списка категорий |
| GET | `/admin/event/list` | Просмотр всех мероприятий |
| POST | `/admin/event/status` | Изменение статуса мероприятия |
| GET | `/admin/user` | Управление пользователями |
| GET | `/admin/user/list` | Получение списка пользователей |
| POST | `/admin` | Создание администратора |
| DELETE | `/user/{id}` | Удаление пользователя |

### 3.6. Управление разрешениями

Доступ ограничен middleware `checkOperator`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/admin/permission/{id}` | Просмотр или изменение разрешений пользователя |
| POST | `/admin/permission` | Сохранение изменений разрешений |

### 3.7. Обращения и вопросы пользователей

Доступ ограничен middleware `checkAuth`.

| Метод | URL | Назначение |
|---|---|---|
| POST | `/ticket` | Создание билета |
| DELETE | `/ticket/{id}` | Удаление билета |
| POST | `/question` | Создание вопроса по мероприятию |

### 3.8. Обработка неизвестных маршрутов

Если пользователь переходит по несуществующему адресу, срабатывает последний маршрут:

```php
Route::get('/{any}', [WebController::class, 'pageNotFound'])
    ->where('any', '.*');
```

Он перенаправляет запрос на страницу 404.

## 4. Middleware и разграничение доступа

В проекте используются middleware для ограничения доступа к определённым маршрутам:

| Middleware | Назначение |
|---|---|
| `checkAuth` | Проверка авторизации пользователя |
| `checkOrganizer` | Проверка прав организатора |
| `checkAdmin` | Проверка прав администратора |
| `checkOperator` | Проверка прав оператора |
